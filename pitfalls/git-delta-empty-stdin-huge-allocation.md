# git-delta crashes on empty stdin with huge allocation

**Symptoms** (grep this section): `delta` exits with `memory allocation of 1970324836974592 bytes failed`; zsh reports `IOT instruction (core dumped)  delta`; `delta --version` prints normally; `printf '' | delta` crashes; `BAT_THEME=` can panic with `something is very wrong if the default theme is missing`.
**First seen**: 2026-05
**Affects**: `git-delta 0.18.2` / `0.19.2` on Linux when `~/.cache/bat/*.bin` was built by an incompatible `bat` version.
**Status**: fixed in repo setup by preferring Linuxbrew `bat` when available, clearing incompatible bat cache, and using a stdin health check for delta.

## Symptom

Running `delta` directly, or invoking Git commands that use `core.pager = delta`, aborts:

```text
memory allocation of 1970324836974592 bytes failed
[1]    2783953 IOT instruction (core dumped)  delta
```

The version check is misleadingly healthy:

```sh
delta --version
# delta 0.18.2
```

But processing even empty stdin reproduces it:

```sh
printf '' | delta
# memory allocation of 1970324836974592 bytes failed
```

With `BAT_THEME` unset, the same binary may show the missing embedded-theme panic instead:

```text
thread 'main' panicked at .../bat-0.24.0/src/assets.rs:252:22:
something is very wrong if the default theme is missing
```

## Root Cause

`delta` can start and report its version, but fails on the rendering path that loads bat syntax/theme assets. The backtrace points at `bat::assets::lazy_theme_set::LazyTheme::deserialize` reading bincode cache data.

The trigger observed here was `~/.cache/bat/themes.bin` / `syntaxes.bin` built by system `bat 0.19.0`, while `delta 0.19.2` embedded `bat 0.26.1`. Clearing the cache makes delta fall back to its embedded defaults and stops the crash. This is not caused by this repo's `core.pager = delta` setting.

This repo previously rebuilt the bat cache after installing the managed Tokyo Night theme, but did not verify whether that cache was compatible with delta.

## Workaround

Immediate recovery is to clear the bat cache:

```sh
bat cache --clear
```

If `BAT_THEME=tokyonight_night` is set, delta may warn that the theme is unknown after clearing the cache; that warning is preferable to the crash. To restore the custom theme safely on a Linuxbrew host, install a newer brew `bat`, rebuild the cache with that binary, and re-test delta:

```sh
brew install bat git-delta
rehash 2>/dev/null || hash -r
bat cache --build
bat --list-themes | rg 'tokyonight_night'
printf '' | delta --no-gitconfig --paging=never
```

`chezmoi apply` is enough only after the active `bat` is compatible with the active `delta`. If apply rebuilds the cache with old apt `bat 0.19.0`, the repo's guard will clear the incompatible cache so delta works, but `delta` will fall back to its default theme.

## Prevention

The `devtools` role validates delta with:

```sh
printf '' | delta --no-gitconfig --paging=never
```

When Linuxbrew exists on Debian/Ubuntu, the `devtools` role installs brew `bat` so the bat cache is generated by a version compatible with brew `delta`. The bat theme run-script rebuilds the bat cache, then immediately runs the same delta health check. If delta fails, the script clears the bat cache so the Git pager keeps working.

On Debian/Ubuntu x86_64, the role installs upstream GNU artifacts:

```text
git-delta_<version>_amd64.deb
delta-<version>-x86_64-unknown-linux-gnu.tar.gz
```

Do not regress the health check to `delta --version` only; that misses this failure mode.
